# 勤怠・給与改修の本番反映手順

この文書は手順だけを定義する。Preview検証中は、Firestore Rules、本番Vercel、本番Firestoreへ反映しない。

## 事前条件

- 対象コミットの全テスト、Firestore Rules Emulator、TypeScript、ESLint、production build、`git diff --check`が成功している。
- 本番Firestoreのバックアップ稼働状態を読み取り専用で確認する。
- `/clock`、通常の打刻、勤怠Excel、確定済み給与に対象外の差分がないことを確認する。
- `payrollSettings/attendanceBreakPolicy`を保存する本部管理者と設定値（閾値180分、控除15分、適用開始日2026-11-01）を確認する。

## ① Firestore Rulesを反映

`firestore.rules`だけを対象projectへ反映する。Hosting、Functions、Storage Rules、Indexesは同時に反映しない。

この段階では旧Vercelアプリが動作し続ける。Rules差分は次の追加許可に限定される。

- `clockLogs`の物理削除拒否は維持する。
- 通常打刻のcreate、担当範囲の通常修正、`isCancelled`による取消は維持する。
- 担当店舗の管理者は休憩打刻だけを論理削除できる。出勤・退勤の論理削除と全打刻の削除取消は本部管理者だけに維持する。
- 非機密の`payrollPeriodLocks`と初期化状態の読み取りを管理roleへ許可する。給与額を含む`payrollRuns`は本部管理者専用のままにする。

旧アプリは新規collectionを使用しないため、通常打刻、打刻修正、休憩削除、勤怠Excel、給与計算・Excelに動作変更はない。

## ② Vercel Productionを反映

①のRules反映とEmulator相当の内容確認に成功した後だけ、対象コミットをVercel Productionへ反映する。

- 通常打刻と勤怠Excelは今回変更していないため従来どおり動作する。
- 打刻修正・休憩削除はサーバーAPIを経由し、給与確定月を拒否する。
- 初期化状態がまだ保存されていない短い移行区間では、安全のため店舗管理者の過去月修正だけを従来と同じ制限で停止する。当月修正、通常打刻、休憩削除、Excel、給与の既存動作は継続する。
- 未確定給与Excelはサーバー再計算のblocking errorがあれば理由を表示して停止する。設定未保存の2026-11以降は`break_policy_not_configured`で停止し、成功表示や空の帳票を返さない。
- 確定済み給与の参照・Excel・明細は保存済みスナップショットを使い、再計算しない。

## ③ HQが一律休憩設定を保存

本部管理者が給与設定画面で、閾値180分、控除15分、適用開始日2026-11-01を確認して1回保存する。

保存トランザクションは設定とともに、既存の確定済み`payrollRuns`から月ごとの非機密な`payrollPeriodLocks`を初期化し、初期化完了状態を保存する。給与額や確定済み従業員スナップショットは変更しない。

完了後は次の状態になる。

- 店舗管理者は月の新旧にかかわらず担当店舗の打刻を修正できる。ただし給与確定済み月は全roleで拒否される。
- 店舗管理者は担当店舗の休憩打刻を論理削除できる。ただし出勤・退勤の論理削除、削除取消、確定済み月の操作はできない。
- 2026-11-01以降の未確定給与に一律休憩設定が適用される。適用日前と確定済み給与は変わらない。
- 未確定給与Excelと給与確定は同じblocking error判定を使用する。

## 段階ごとの確認（書込み操作は承認された確認データだけで実施）

各段階で、ログイン、通常打刻画面、管理画面、担当範囲の修正UI、休憩削除UI、勤怠Excel、給与画面を確認する。①と②の間は旧アプリ、②と③の間は移行時安全停止、③後は確定月索引による制御であり、物理削除・給与再計算・確定済み金額の更新は行わない。
